# Recoverable Research Value — TREM

## Surviving mechanisms

### 1. Layered retrieval
Depth-indexed storage is a real software mechanism. Deepest-first lookup can represent specificity or authority tiers if those semantics are explicitly defined.

### 2. Provenance-preserving retrieval ladder
The strongest upgrade is:

[
LOCAL 
eq EXTERNAL 
eq SYNTHETIC
]

Every returned value should carry its source class. This maps naturally to governed agent systems where inferred material must not masquerade as retrieved evidence.

### 3. Cache-on-retrieval
An externally retrieved record can be cached locally with source provenance retained. This is a practical runtime optimization.

### 4. Bounded fallback
Synthetic reconstruction can remain useful if explicitly labeled and denied authority. It should never silently become stored truth.

### 5. Future adaptive-depth experiment
The historical recursion-control idea survives only as a research hypothesis. It needs a measurable state such as task uncertainty, retrieval conflict, unresolved dependency count, or benchmark error—not undefined "recursion energy."

### 6. Future semantic clustering
Replace "fractal attractor" with a testable clustering hypothesis: embeddings/representations of recurring concepts may form stable neighborhoods under a declared representation and distance metric. Measure stability rather than assume fractality.

## Potential LightMathematics value
TREM could become a small runtime component supporting provenance-aware agent retrieval and unresolved-obligation handling. It should not become a Sigma merely because it is part of LightMathematics; first determine whether the object is a mathematical relation, an operator protocol, or software infrastructure.
